## 3. Туршилтын зорилго

Уншлагын жагсаалт веб аппликейшний ажиллагааг хар хайрцгийн exploratory testing аргаар шалгаж, 60 минутын туршилтын session зохион байгуулахад оршино. Туршилтын үеэр аппликейшний үндсэн үйлдэл, оролтын өгөгдлийн баталгаажуулалт, хайлт, устгал, давхардсан өгөгдөл, интерфэйсийн харагдах байдал болон API хүсэлтийн боловсруулалтыг шалгана.

Илэрсэн асуудлуудыг давтан шалгаж, алхамчилсан тайлбар, хүлээгдэж буй болон бодит үр дүн, холбогдох нотолгоо бүхий bug report хэлбэрээр баримтжуулна.

## 4. Туршилтын хамрах хүрээ

Туршилтаар дараах чиглэлүүдийг хамруулсан.

- Ном нэмэх, хайх, устгах үндсэн үйлдлүүд.
- Заавал бөглөх талбаруудын баталгаажуулалт.
- Оны утгын формат болон зөвшөөрөгдөх хязгаар.
- Ижил номыг давхар нэмэх үеийн ажиллагаа.
- Хүснэгтийн мөрийн тоолуурын нийцэл.
- Урт текст болон товчны харагдах байдал.
- Хуучин хувилбарын холбоосын ажиллагаа.
- Буруу бүтэцтэй JSON хүсэлтэд API-аас буцаах хариу.

## 5. Ашигласан аргачлал ба туршилтын tour-ууд

### 5.1. Charter

`charter.md` файлд туршилтын зорилго, хамрах хүрээ, орчны мэдээлэл болон tour-уудыг тодорхойлсон.

### 5.2. Үндсэн ажиллагааны шалгалт

Ном нэмэх, хайх, устгах үйлдлийг шалгаж, хэрэглэгчийн үндсэн урсгал зөв ажиллаж байгаа эсэхийг үнэлсэн.

### 5.3. Буруу оролтын шалгалт

Хоосон талбар, текстэн болон бутархай он, зөвшөөрөгдөх хязгаараас гадуурх утга, давхардсан ном зэрэг нөхцөлүүдийг шалгасан.

### 5.4. Интерфэйсийн шалгалт

Хүснэгтийн тоолуур, урт текстийн байрлал, товчны харагдах байдал болон хуучин хувилбарын холбоосыг шалгасан.

### 5.5. API шалгалт

Буруу бүтэцтэй JSON хүсэлт илгээж, HTTP төлөв болон буцаасан хариуны агуулгыг шалгасан.

## 6. Туршилтын үр дүн

Туршилтын явцад дараах асуудлуудыг тэмдэглэж, холбогдох тайлан болон нотолгоог бэлтгэсэн.

| Алдааны дугаар | Илэрсэн асуудал | Нотолгоо |
|---|---|---|
| BUG-01 | Буруу бүтэцтэй JSON хүсэлтэд зохисгүй амжилтын хариу буцаасан | `evidence/bug-api-01-curl.txt` |
| BUG-02 | Хоосон талбартай өгөгдөл нэмэгдэх боломжтой | `screenshots/bug-02.png` |
| BUG-03 | Ижил номыг давхар нэмэх боломжтой | `screenshots/bug-03.png` |
| BUG-04 | Хуучин хувилбарын холбоос алдааны хуудас харуулсан | `screenshots/bug-04.png` |
| BUG-05 | Хүснэгтийн мөрийн тоо болон тоолуур зөрсөн | `screenshots/bug-05.png` |

**Тайлбар:** Дээрх асуудлуудын тайланг `bugs/` хавтаст тус бүрээр нь хадгалсан. Эцсийн үнэлгээнд оруулахын өмнө шинээр эхлүүлсэн аппликейшн дээр дахин шалгасан үр дүнтэй тулгана.

```

```

## 9. Нотолгоо ба тайлангийн файлууд

- `charter.md` — туршилтын зорилго, хамрах хүрээ, tour-ууд.
- `session-report.md` — session-ийн үргэлжилсэн хугацаа, тэмдэглэл, үр дүн, хязгаарлалт.
- `bugs/` — алдааны тайлангууд.
- `evidence/` — API хүсэлтийн текстэн нотолгоо.
- `screenshots/` — интерфэйсийн дэлгэцийн зургууд.
- `test-notes/` — туршилтын Excel хүснэгт.

## 10. Debrief — Туршилтын дараах дүгнэлт

Supermodel tour нь ном нэмэх, хайх, устгах болон интерфэйсийн ажиллагааг шалгахад чиглэсэн. Энэ хүрээнд BUG-04 (хуучин хувилбарын холбоос) болон BUG-05 (тоолуурын зөрүү) бүртгэгдсэн. Couch Potato tour нь хоосон талбар, буруу он болон давхардсан номын нөхцөлийг шалгахад чиглэсэн бөгөөд BUG-02 (хоосон талбар) болон BUG-03 (давхардсан ном)-ыг баримтжуулсан. Saboteur tour-аар буруу JSON хүсэлт илгээж BUG-01-ийг бүртгэсэн. Эдгээр bug-ийн тайлан, screenshot болон API нотолгоог тус тусын файлд холбосон.

Туршилтын тэмдэглэлд бүрэн бус хэсэг байгаа тул T25-ийн үр дүнг баталгаажсан гэж үзээгүй. Session-ийн үйлдэл бүрийн цаг бодит цагт тэмдэглэгдээгүй учир тайлангийн хугацааны хуваарилалт ойролцоо сэргээн тооцоолол юм. Шинээр эхлүүлсэн аппликейшн дээр BUG-01–BUG-05-ыг дахин шалгаж баталгаажуулах шаардлагатай. Өөр хөтөч, нэмэлт өгөгдөл болон холбоосын бусад нөхцөлийг бүрэн туршаагүй байж болох тул тэдгээрийг цаашдын шалгалтад үлдээнэ. Playwright зэрэг автомат тест нь давтагддаг үйлдлүүдийг шалгахад тустай боловч энэ лабораторийн UI-ийн өнгө, урт текстийн байрлал зэрэг харагдах байдлыг хүний нүдээр ажиглах нь мөн чухал. Playwright ашигласан эсэхийг зөвхөн бодитоор ажиллуулсан тохиолдолд тайланд баталж бичнэ.

## 11. Хиймэл оюун ухаан (AI) ашигласан тухай

Лабораторийн ажлын баримт бичгийн бүтэц боловсруулах, Markdown форматыг засах, Git командын хэрэглээг ойлгох болон туршилтын үр дүнг эмхэтгэхэд ChatGPT зэрэг хиймэл оюун ухааны хэрэгслийг туслах зорилгоор ашигласан. Туршилтын бодит үйлдэл, дэлгэцийн зураг болон API хүсэлтийн үр дүнг өөрөө шалгаж баталгаажуулах шаардлагатай. AI-аас санал болгосон агуулгыг бодит туршилтын үр дүнтэй тулган нягтална.
